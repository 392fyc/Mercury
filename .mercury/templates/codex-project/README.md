# Portable Codex project template

This directory is the source for a small generated Codex layer that downstream
repositories can adopt without copying Mercury's project configuration.

The manifest publishes only the declared `mercury-*` files into the target
repository's `.codex` directory. Downstream-owned agents, rules, skills, and
project documents are overlays and remain outside the generator's ownership.

## Contents

- `agents/`: implementation, review, and blind acceptance roles.
- `rules/`: repository-independent Git safety rules. They block the listed
  direct `git push` and Git global-option token forms; each downstream
  repository supplies its own controlled publication entrypoint.
- `project/`: the task, evidence, and receipt exchange contract.
- `manifest.json`: the deterministic allowlist for generated files and the
  explicitly declared, schema-fixed `mercury-template.lock` basename consumed
  by the sync tool.

The template intentionally excludes repository configuration, hooks, local
paths, credentials, ports, runtime state, and calls to repository-specific
scripts. A target repository supplies those concerns in its own project layer.
The convenience rules for direct `switch` and `checkout` forms do not claim to
enumerate every Git option; repository policy remains responsible for branch
selection and review requirements.
These prefix rules are defense in depth, not an arbitrary shell-command
inspector or a complete Git option parser. Shell trampolines and unlisted token
forms must obey project instructions and the controlled entrypoint, while
remote branch protection is the final enforcement boundary for publication.

Both sync modes require the target repository and the exact 40-hex-character
Mercury source commit. The commit must exist in the Mercury repository that
contains the sync tool. The manifest and every published template file are
read directly from that commit's Git tree, so checkout line-ending settings do
not change generated bytes or hashes:

```text
<sync-tool> check --target <target-repository> --source-commit <40-hex-commit>
<sync-tool> apply --target <target-repository> --source-commit <40-hex-commit>
```

Use `check` to inspect drift without writing and use the explicit `apply` mode
to update a target. Never copy this directory by hand: the generated
`.codex/mercury-template.lock`, explicitly declared by `manifest.json` and
fixed by the manifest schema, is part of the provenance and ownership
contract. When an updated manifest drops a generated path, `apply` removes it
only if its content still matches the previous lock; a downstream modification
is reported as a conflict before any generated file is changed. A pre-existing
lock from another `source_repo`, or one that cannot be reconstructed byte for
byte from its recorded Mercury commit, is rejected before any write or
deletion.

`apply` replaces each generated file atomically within its destination
directory and writes the authenticated lock last. The operation is not a
whole-tree transaction: an operating-system or I/O interruption can leave a
partial update, but the absent or stale lock makes the next `check` report
drift, and rerunning `apply` is safe. No transaction journal is created.

The portable synchronizer assumes non-adversarial concurrency. The caller must
hold exclusive control of the target tree for the duration of `check` or
`apply`; defending against another process that deliberately swaps a directory
for a junction between safety checks is outside this layer's guarantee.
