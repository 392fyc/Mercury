# Harness 报告的分类规则验证（2026-11）

Issue：[#755](https://github.com/392fyc/Mercury/issues/755)。这里记录 `tools/harness_monitor/rules.py` 为什么可信、可信到什么程度。原始样本含对话内容，只留在本机，不进仓库。

## 要回答的问题

分类规则把一次工具调用判成“读了记忆”“查了网络”等类别。我们要知道两件事：

- **精确率**：规则说是这一类的调用里，有多少真的是。
- **召回率**：真正属于这一类的调用里，规则找到了多少。

宿主（Claude、Codex）和 7 个类别组成 14 格，每格单独判断。

## 方法

1. 规则先冻结并记录哈希，方案先写好，再抽样。抽样种子固定。
2. 只用规则没见过的调用，共 901 条，排除私人项目。
3. Sonnet 和 Opus 互不知情地标注全部样本，两者一致即为标准答案。883 条一致；其余 18 条交第三个模型 Fable（同样是 Claude 系列）裁定取多数，2 条没有多数，从分母剔除。主会话不参与裁定。
4. 过线标准：精确率的 95% Wilson 下限不低于 80%，且召回率的“关键词下限”不低于 70%。

关键词下限假设“完全不含相关关键词的调用几乎不属于这一类”。不用这个假设的严格下限 14 格都低于 70%，要压到 70% 以上，每个宿主需要几百到上千条随机样本。

## 结果

每格写的是：精确率 / 估计召回率（关键词下限）。

| 类别 | Claude | Codex |
|---|---|---|
| 记忆读取 | 31/32 / 100%（42%）未验证 | 39/40 / 90%（77%）可用 |
| 跨 lane 消息 | 37/40 / 100%（68%）未验证 | 40/40 / 83%（76%）可用 |
| skill 文档 | 33/39 / 89%（46%）未验证 | 39/40 / 100%（77%）可用 |
| 知识库 | 38/40 / 93%（82%）可用 | 39/40 / 88%（77%）可用 |
| 规则文件 | 36/39 / 96%（84%）未验证 | 39/40 / 94%（84%）可用 |
| 网络查询 | 40/40 / 100%（93%）可用 | 40/40 / 52%（48%）未验证 |
| GitHub | 40/40 / 99%（97%）可用 | 40/40 / 94%（84%）可用 |

9 格可用，5 格未验证：

- **Claude 记忆、跨 lane 消息**：定向样本里没有漏判，但这两类调用少、候选多，样本量压不低上限。
- **Claude skill 文档**：只算哈希、查 BOM、看 git 日志或写入 `SKILL.md` 被算成读取。
- **Claude 规则文件**：脚本里只把 `AGENTS.md` 当字符串，被算成读取。
- **Codex 网络查询**：Codex 用 `js` 工具驱动浏览器，规则认不出，且这违反了关键词假设。52% 主要由 2 条随机样本推算，不要直接引用。

## 局限

- 三位审查者都是 Claude 系列模型，不是不同厂商。
- 审查者只看调用内容，看不到执行结果和之前的工作目录。
- 记忆目录下的证据 JSON 按路径算作记忆读取。
- `lane-bus wait` 不算消息读取。`Agent`、`SendMessage` 和 Claude 浏览器工具不在范围内。
- 结论只代表验证时的日志。工具和模型习惯变了要重新抽检。

## 工具的实现核对

2026-11-05 在真实日志上运行 `monitor.py`：首次 31 秒，增量约 1 秒，结束后没有残留进程。用独立代码按验证时的过滤条件重算，两个宿主 7 个类别和总数共 16 个数字全部一致。
