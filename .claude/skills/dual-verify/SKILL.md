# 双上下文审查

仅在用户明确要求或既定计划规定时，使用两个彼此独立的上下文审查同一份基线、改动和验收条件。本技能不要求固定模型或推理强度，也不代表跨厂商验证。

- 给两个审查上下文安排不同重点，例如一侧检查需求、逻辑和回归，另一侧检查边界、错误处理和仓库约定。
- 要求各自提供有证据支持的问题、文件位置、影响和不确定性；没有发现问题时也明确说明。
- 主会话合并重复项，核对分歧并复查关键证据。
- 审查报告不自动授权修改、提交、发布或其他外部操作。

这项审查不替代仓库要求的 review 标记、审批或检查。遵守受保护分支及项目规则。
