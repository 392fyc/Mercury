# 有界实现与验收

普通实现请求直接按任务本身处理。本技能不是默认流程，也不会自行重试、提交、推送、创建 PR、修改远程 Issue 或清理工作目录。

1. 对照用户要求和仓库约定，明确目标、允许改动路径和验收条件；仓库要求时关联已有 Issue。
2. 主会话确定范围并整合；按需使用 Sonnet dev 子代理实施。
3. 仅在当前计划需要独立验收时，使用 Opus acceptance 子代理按验收条件核对变更与检查证据。不得把它变成每项工作都强制的双路审查。
4. 保留无关改动，只修改任务所需内容，并运行与风险相称的最小项目检查。
5. 未满足验收条件或发现范围问题时，报告具体缺口；不自动扩大任务或无限迭代。
6. 返回改动路径、逐项验收证据、检查结果和未解决限制。

需要提交、推送、创建 PR 或其他外部动作时，依据当前任务已有授权并遵守 AGENTS.md 与 scripts/codex/git-safe.ps1。
