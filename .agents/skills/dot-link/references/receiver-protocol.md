# dot 接收与回传协议

协作版本为 `dot-cooperation/2`，签名信封仍使用 `dot-local/0.2`。本协议规定已有授权任务的接收、结果交付和消费回执，不授予新的工具、账户或材料权限，也不建立定时任务。Mercury 管理协议源码；项目自己的 workflow 定义测试内容和业务通过条件。

## 读取与固定版本

本地从用户级 dot-link 技能读取本文件及共享配置；新会话沿用现有签名身份，只登记经过核实的新来源与回复地址。首次公钥登记、换钥和撤销沿用既有真实人类确认要求。

TASK 的 `payload.cooperation_protocol` 包含 `version`、`sha256` 和可读取的 `page_id`。SHA256 是本协议文件原始 UTF-8 字节的摘要。接收端先验签，再读取文件原文，核对版本与摘要，将实际读取的文件和处理状态保存到自己的持久任务目录。私有 Page 的编辑、收到的消息或版本编号不能替代身份核验和任务授权。版本不一致时返回具体差异，不默默沿用旧版本。

ACK 记录协议实际读取的版本与摘要、真实来源、回复地址和采用的结果读取路径。v2 另记录持久服务的 generation、固定身份和路由绑定。没有 ACK 或 ACK 不一致时，本地不声称协议已经在 dot 生效。首次采用 v2 只发送只读 HELLO；接收端验证原件和持续人类授权，确认旧协议不得再启动任务后，返回 ACK。本地再启用经过审查的服务配置。之后任务均先读取服务的实际状态，不从聊天或临时文件推断启用状态。

## 身份与真实人类授权

接收端分别记录 `identity_verification`、`human_source_readability` 和 `task_authorization`。验签只证明发送身份；消息到达不证明本地历史可读；文件摘要只证明字节一致。

接收端在自己可读取的原始人类指令或可信用户规则中核对参与者、项目、任务种类、允许材料和接收位置。`payload.human_source` 仅提供候选定位，发送方的授权结论、代理转述和 Page 都不能自行增加权限。持续授权存在且覆盖当前步骤时，直接执行已授权的正常操作，不按请求批次、新本地会话、失败诊断或已覆盖的必要重跑重复询问。

本地历史不可读时，保留准确目标、工具和原始错误，并核对接收端可直接读取的持续人类授权。读取失败不撤销这份独立授权，也不触发换钥或重新配对；原因未知就保留未知。确实没有覆盖当前操作的可核实依据时，只暂停该操作，返回 `authorization_missing` 及缺失范围。范围外动作、产品强制确认和用户保留的单独授权按原约定处理，GitHub 评论或回复须有明确授权。

持续授权按实际参与者核对；某个 Codex 安装的授权不能自动推广到新的 Claude Code 安装、账户、设备或其他代理。新模型名称不作为身份或权限证明。

## 接收与去重

每个新任务创建唯一 `task_id`，每个新请求创建唯一 `request_id`；任务的正式重跑增加 `attempt` 并使用新请求。消息保留真实 `source_thread_id`、`reply_thread_id`、`recipient_thread_id`、递增 `seq`、`in_reply_to`、随机 nonce 和期限。传输工具提供原生来源时必须与签名正文匹配。

v2 的唯一登记权威是既有 Private Agent Events 服务配置的独立任务账本，位于宿主持久目录。事件队列的 consumed 状态不代表任务执行。云端工作目录仅作缓存，不创建本地替代账本。服务不执行命令，不判断任务授权，也不替接收端验签；服务权限来自既有认证身份，发送者登记和接收者领取分别限定到固定 principal。

签名正文必须在 `payload.replay_generation` 中绑定服务当前 generation，`payload.cooperation_protocol.sha256` 必须匹配服务固定摘要，期限不超过 24 小时。发送方用既有固定身份生成信封，再以 `dot_link.py admission` 从验签后的 TASK 导出固定元数据，使用既有认证客户端登记为 `admitted`。登记原子固定 request_id、nonce、task_id/attempt、正文摘要、身份、路由、generation、期限和状态。同一 request_id/nonce 的冲突拒绝；同一任务的运行结果未知时不能用新 attempt 绕过。

接收端先核验原信封的固定公钥、完整签名、期限、路由、协议和真实人类授权，再用 `task_ledger_status` 读取实际持久记录，逐项比较签名正文与登记元数据，随后调用 `claim_task(request_id, body_sha256, generation)`。只有本次调用明确返回 `start_granted=true`、`state=running`，且所有独立核验通过，才可以启动一次任务。`start_granted` 只解决重复启动，不授予业务权限。登记、领取或回包失败都不能先执行。

同一签名请求重发只返回已有 ACK、进度或结果引用，不重新执行。领取成功后响应丢失、进程中断或云目录消失，都不会归还启动机会；重复 claim 返回 `start_granted=false`。此时先回读已有原件，未知结果保持 blocked。去重记录不在任务关闭时删除。只读 HELLO 不领取任务、不建账本，不运行 Godot。

### 持久目录丢失与旧代隔离

账本文件、完整性、固定配置或 generation 任一不一致，服务必须拒绝登记和领取，不能自动新建空库。配置与账本分开放置，分别只读和持久读写挂载；新云会话经既有认证工具读取这份权威，不依赖上次云目录。

有可信完整原件时先核验再恢复。无法证明原件完整时，在已授权的修复范围内，由本地主代理保留原记录和未知结果，明确列出旧任务的处置，独立审查后初始化全新的 generation 和独立文件。该过程不是恢复历史唯一性：接收端必须明确拒绝所有旧协议、旧代和缺 generation 的执行请求，旧任务维持原 FAIL/BLOCKED/部分关闭，不靠改 ID 重跑。只有新的、范围明确的任务可在新代登记。

初始化不覆盖任何原件，网络 API 不提供初始化、清空或换代接口。备份采用 SQLite backup API，并标为仅归档，不能把可能落后的快照直接启用为活动账本。服务代码回滚不回滚账本；若需要停用，保持任务拒绝执行。跨会话继续已确认的同一代，不为普通重连、认证刷新或新会话反复换代。

发送者的 `seq` 只用于自己的消息顺序。`in_reply_to` 指向被回复的请求，不能只凭文件名或标题关联不同任务。取消只影响指定任务，用户撤销持续授权与取消单次任务分别记录。

## 状态与回传

正常顺序为 TASK、ACK、RESULT、RECEIPT、关闭确认。持久状态依次为 `admitted`、`running`、`delivered`、`readback_verified`、`closed`；失败可从 running 进入 `blocked` 或 `failed`。接收端通过 `transition_task` 保存 running 到 delivered/blocked/failed，发送方核对原件后保存 delivered 到 readback_verified，接收端验签消费回执后保存 readback_verified 到 closed。每次转换绑定原 TASK 的正文摘要、generation、预期状态和相应证据摘要；同状态同证据可幂等回读，冲突拒绝。成功交付与业务通过分开记录，`domain_verdict` 不由传递状态推导。

ACK 至少含任务及请求 ID、关联请求、协议版本与摘要、三个独立核验状态和回复地址。RESULT 包含相同关联字段、实际执行次数、开始与完成状态、结果读取位置、完整文件清单、失败项与环境限制。结果读取位置在 TASK 中固定，不能由未核实的回信改到其他接收方。

每个制品记录 `page_id`、原文件名、精确 `reference`、字节数和 SHA256。原 PNG、完整日志和原始结果按项目要求保留，摘要针对原文件字节计算。Page 链接、缩放图、退出码或脚本成功不能代替原文件和业务验收。

有固定接收端签名身份时核对 RESULT 签名；当前没有该身份时，必须从已核实的原生接收会话读取 RESULT 和精确制品引用，再验证原文件。不得把发送方的公钥冒充为 dot 的公钥，不把普通 Page 编辑作者或文件摘要当作接收端身份认证。

反向推送可用时向核实的回复地址发出结果通知；已知该目标不可用时，直接保存 RESULT 到接收端原会话及私有 Page，供本地主动读取。不因该目标的同一已知错误重复推送或索取人工转交。仅在路由能力未知时尝试一次，失败则记录工具、方向、目标和原始错误，切换到 TASK 已指定的读取路径。本地在当前工作回合中使用原生等待和读取；后台轮询或空闲会话唤醒需要另外实现和授权。

本地实际读取原文件，核对关联字段、字节数、摘要及项目验收条件，再发送签名 RECEIPT。回执区分交付验证与业务结论，并列出仍未核实的项。dot 验签后保存消费回执，返回关闭确认；缺少回执时维持 `delivered`，不能声称本地已消费或接受结果。

## 模拟任务验收

模拟请求标为 `transport_mock`，只使用合成输入、隔离目录和小型文本制品，不运行 Godot，不改生产代码，不复用真实测试的业务通过结论。

发送方提供任务 ID、请求 ID和随机 challenge。接收方创建 `mock-result.txt` 与 JSON 结果，回显关联字段和 challenge，并记录 `godot_executed=false`、`production_modified=false`、实际执行次数及原文件清单。本地先独立计算预期文本字节，再从私有 Page 读取原文件并比较字节和摘要。

完全相同的已签名 TASK 重发一次，应返回已有结果，执行次数和原文件字节不变。随后本地发送消费回执，接收端保存并确认关闭。只有实际完成这一往返才能记为模拟链路通过；原生会话与 Page 路径通过不能代替网站 API、机器凭据或真实 Godot 测试的验收。
