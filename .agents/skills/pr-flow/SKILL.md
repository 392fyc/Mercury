# PR 与 Argus 审查

只执行用户要求的阶段，并完成本轮有界检查。提到 PR 本身不代表要启动完整的创建、修复、推送和合并流程。本技能不扩大评论、提交、推送或合并权限。

## 检查与处理

- 按仓库约定确认目标分支：Mercury 使用 develop，Argus 仓库使用 master；其他仓库遵循其文档或既定流程。不能仅因 develop 分支存在就选它。
- 查看当前 PR 状态、head、reviewDecision、最新相关 Argus review 和未处理意见。报告结论时说明它对应的 head。
- 阅读所有相关意见，区分需要修复、不同意或仍需澄清的事项。不要手动 resolve Argus review thread；由修复检测或 Argus 的回复处理流程更新状态。
- 修复推送后，旧的 APPROVED 不代表新 head 已通过。等待并核对针对当前 head 的最新 review，再依据 reviewDecision 报告状态。
- 按当前任务、会话中已有授权和仓库约定执行对应 PR 阶段；不要要求用户重复授权。技能本身不会扩展授权。创建或改动 PR、提交、推送、合并或删除分支，仅在当前授权覆盖该动作时执行；向外发布评论或回复须有明确授权。合并还须满足仓库要求的审批、检查和未解决意见条件。

在本轮合理有界的等待中继续推进已授权且可完成的工作。若审查或检查仍未就绪，报告已完成内容、待处理依赖和当前证据。只有用户明确要求未来持续监控时，才使用当前环境支持的自动化，并说明检查频率与停止条件；否则不安排后续轮询。
